# Local semantic retrieval: candidate evidence

**Publication remains blocked.** The fresh V3 set passes, but the 10,000-note v8 suite still
misses two semantic targets and exceeds its existing 100 ms p95 latency gate. These authored
synthetic fixtures are regression/generalization checks, not a claim of universal accuracy.
No personal notes were used. Public Alpha 25 artifacts were not changed.

## What changed

The candidate uses EmbeddingGemma 300M q4 for candidate retrieval and Ettin 150M ARM-int8 for
local relevance scoring. It shares semantic ranking between Notes and connected-tool Recall,
removes the UI rule that let incidental keyword hits hide semantic results, and fuses the two
ranking signals. The native UI offers one explicit enable action, aligned with other Settings
controls. Download: 375,310,760 bytes. Model weights are not bundled or sent note content.

Relevance admission remains score >= 3; the semantic candidate floor is 0.20. The bounded
shortlist contains up to 20 semantic and 20 strong lexical candidates. Literal phrases and
identifiers remain searchable beyond that bound. The final ranking is equal-weight reciprocal
rank fusion, `1 / (2 + zeroBasedRank)` from each available signal, plus literal priority.
Ranking scores are not probabilities or proof that a note answers the question.

Model manifests, revisions, hashes and pipeline identities are in the source catalog. The
embedding pipeline did not change in this iteration; existing document vectors are reusable.
The final relevance identity ends in `afternote-2` to invalidate older search cursors.

## Fresh evaluation

V2 was frozen at `bef4dbe`, before the first reranker candidate. V3 was frozen at `2b1f09a`,
before rank fusion. Their hashes are asserted in `scripts/validate-semantic-model.test.ts`.
The first V2 results were preserved after inspection. V3 was evaluated only after committing
the new candidate at `206faf7`; it was not used to select cutoffs, models or fusion constants.

| Fixture / engine | Agent intended hit@5 | UI intended hit@5 | Agent / UI MRR | Unsupported rejected, agent / UI |
| --- | --- | --- | --- | --- |
| V2 embedding-only baseline | 24/24 | 10/24 | .938 / .396 | 8/12 / 8/12 |
| V2 initial reranker | 24/24 | 24/24 | 1 / 1 | 11/12 / 11/12 |
| V3 embedding-only baseline | 16/16 | 10/16 | .938 / .563 | 6/8 / 5/8 |
| V3 final fused candidate | 16/16 | 16/16 | 1 / 1 | 8/8 / 8/8 |

Citations passed in every row. The candidate returned hybrid results for all UI queries in both
fresh sets, without deadline fallback. V2's false positive was a presentation-colors note for a
jewelry-safe combination question. The final candidate has not been re-evaluated on V2 and must
not inherit the initial candidate's exact V2 result as its own.

On this M2 Mac with 16 GB RAM, V3 candidate p95 was 139 ms for agent recall and 287 ms for UI
search, with sampled peak process RSS of 1,433 MiB. V2 initial-candidate p95 was about 357 ms
and sampled peak RSS 1,377 MiB. These are individual runs, not latency/memory guarantees.
The V3 baseline briefly overlapped TypeScript checking at startup, so its timings are not an
isolated performance comparison. Candidate V3 inference ran after that check completed.

## Known development and scale cases

| Engine | V1 intended hit@5 | V1 MRR | V1 unsupported rejected | v8 semantic hit@5, 10k notes | v8 semantic MRR | v8 p95 |
| --- | --- | --- | --- | --- | --- | --- |
| Initial reranker | 27/28 | .946 | 16/16 | 11/14 | .786 | 834 ms |
| Fused candidate | 27/28 | .964 | 16/16 | 12/14 | .857 | 718 ms |

V1 has been used for development/model selection; these are not unseen scores. Both UI and
agent V1 results agree. The remaining V1 miss is the holiday-house detour query.
The fused candidate recovers the launch blocker from repetitive shipping-label-printer noise.
It still rejects the museum-outing and espresso-drink targets, although both enter the shortlist.
Both scale candidates reject every unsupported v8 question and preserve valid citations.
The earlier embedding-only Balanced baseline found 13/14 semantic v8 targets; this candidate's
scale recall is therefore still a regression, despite the substantial fresh UI improvement.

Scale reports replay 10,001 document slices from a SHA-256-keyed cache generated by the same
pinned embedding pipeline. Query embeddings, SQLite retrieval and reranking execute normally.
A repeat using the checked-in scale CLI reproduced the same quality results (624 ms p95, still
failing the 100 ms gate). These runs measure ranking quality and query latency; **they are not fresh indexing or memory
benchmarks**. Earlier fresh embedding-only indexing took about 12m27s for 10,000 notes; this
iteration does not establish a new initial-indexing figure. Initial V1 reranker timings were
contended and should not be used as performance evidence.

## Process restart probe

With the 20 V3 notes already indexed in an isolated file database, separate fresh Bun processes
opened the existing index and immediately searched the first V3 query. UI found the target in
1,288 ms with hybrid status; agent Recall found it in 1,442 ms. Neither used a model warmup in
that process. This is not an OS-cache-cold benchmark or a large-library restart test. The agent
measurement is close to the internal 1,500 ms semantic deadline, so cold-start headroom remains
a usability concern rather than a proven margin. Raw outputs are in `cold-recall-*.json`.

## Rejected experiments

Known-case probes compared MiniLM and Ettin 32M/68M/150M; 150M was selected before V2.
Ettin 400M was later downloaded at the revision in `ettin400-manifest.json` and tested on known
V1 and v8 candidates. Its V1 separation improved, but v8 still rejected the launch blocker,
museum outing and coffee order. It was not integrated. Removing appended source metadata had
mixed effects and was not adopted. No case-specific query rewrites or synthetic-note keywords
were added to the product.

The raw 400M artifacts here are diagnostic reports from a prototype, not full end-to-end quality
reports. The weights themselves remain outside the repository.

## Reproduce

Use the exact public model files listed in `apps/local/src/semantic-model-catalog.ts`, laid out
with the Ettin artifacts under `reranker/`. Every artifact is hash-verified before evaluation.
Inference is offline. Run serially, without tests or other inference jobs competing for CPU:

```sh
bun scripts/evaluate-semantic-retrieval.ts MODEL_DIRECTORY v3 REPORT_PATH baseline
bun scripts/evaluate-semantic-retrieval.ts MODEL_DIRECTORY v3 REPORT_PATH
bun scripts/evaluate-semantic-scale.ts MODEL_DIRECTORY SCALE_REPORT_PATH
```

The scale command performs fresh indexing by default. An optional third argument accepts the
synthetic vector cache and explicitly labels its report as a replay. Missing text hashes or an
embedding-descriptor mismatch fail instead of silently substituting vectors. The roughly 40 MB
cache is not committed; a full fresh run does not require it.

```sh
AFTERNOTE_TEST_MODEL_DIRECTORY=MODEL_DIRECTORY bun test apps/local/src/compiled-reranked-semantic.test.ts
bun run typecheck
bun run test
```

Final regression suite: **631 passed, 10 skipped, 0 failed** (641 tests across 77 files).
TypeScript checking passed. The skipped compiled real-model test was run separately and passed
(1 test, 4 assertions); other opt-in/signed-environment checks remain separate.

The compiled test passed on the candidate: isolated installation, all pinned file checks,
re-discovery, 768-dimensional embedding and relevant/unrelated passage scoring through the
release's text-only Bun compilation and staged ONNX native libraries. It does not substitute
for signing/notarization or clean-user acceptance.

## Product policy and publication gates

The pending product choice is whether to return explicitly marked related context when the
requested detail is not actually saved. This evidence retains conservative admission and the
original unsupported-zero-results gate. A different policy needs explicit UI/tool semantics and
its own evaluation; it must not silently convert these failures to passes.

Before publication: resolve retrieval quality at scale, decide the relevance policy, establish
acceptable end-to-end response times, and run a new signed build's clean-user/connector checks.
Published Alpha 25 Light installations retain their existing behavior until explicit upgrade.
Earlier unpublished development Balanced snapshots lack the new bundle files and require the
explicit repair action; exact search remains available.
